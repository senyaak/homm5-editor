# Working in this repo

How work is done here — the owner's standing decisions and the lessons that
became rules. Each file is one subject; [CLAUDE.md](../../CLAUDE.md) keeps the
one-line version of the rules that matter most.

- [e2e.md](e2e.md) — writing a spec: every gesture checked by its outcome, maps built through the window, chains, live runs
- [editor-design.md](editor-design.md) — data shown as saved, presets fill every field, the gesture named, deleting, refusals, our own art
- [git.md](git.md) — attribution, what is committed and pushed, the changelog, a public repo
- [mods-and-the-engine.md](mods-and-the-engine.md) — where content lives, one mod, faction files apart, new tables in our DLL, one door for a new term
- [native.md](native.md) — hooks and arity, vtables, logs in development builds only
- [numbers.md](numbers.md) — matching the engine number for number: FPU state, rounding, aligning two runs
- [reverse-method.md](reverse-method.md) — reading the executable, and the answers that look right and are not
- [scope-and-docs.md](scope-and-docs.md) — what a task includes, and where a thing is written
- [shell-and-files.md](shell-and-files.md) — Windows shells and the agent's tools: the ways a file gets damaged
- [testing.md](testing.md) — running the suites, what to run for a change, what makes a test worth having
- [the-game.md](the-game.md) — never launching a window, handing a check to the owner, installs and copies
